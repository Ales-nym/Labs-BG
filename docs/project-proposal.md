## 1. Название и организация

- **Название системы:** Учетные записи
- **Организация/подразделение:** Отдел IT
- **№ из таблицы примеров:** Тема 24 - "Учетная запись в системе"

## 2. Главная сущность и справочник

- **Главный объект (одна запись процесса):** заявка на доступ
- **Справочник (вторая таблица, ссылка числом):** информационная система
- **Поле-ссылка:** system_id

## 3. Роли и права

сотрудник назначает или админ?

| Роль | Создает | Назначает | Меняет статус | 
|---|---|---|---|
| Сотрудник | да | нет | нет |
| Администратор | нет | нет | да |

## 4. Сценарий в одно предложение

Сотрудник создает заявку на доступ -> администратор назначает исполнителя на заявку -> администратор меняет статус заявки

## 6. Что не входит в семестр

1. Реальная выдача учётных записей и интеграция с Active Directory / LDAP — система только фиксирует заявки, но не управляет реальными доступами.
2. Мобильное приложение — только веб-версия.
3. Печать заявок и отчётов.
4. Уведомления по email/SMS — сотрудник видит статус только в системе.
5. Интеграция с 1С и другими внешними системами.

## 7. Запас под ВКР

1. Согласование заявки руководителем подразделения (третья роль) и автоматическое истечение срока доступа.
2. Журнал аудита — история всех действий администратора и изменений статусов.
3. Интеграция с Active Directory / LDAP для реальной выдачи и отзыва доступов.
4. Уведомления по email о смене статуса заявки.
5. Разграничение видимости заявок по подразделениям (мультитенантность).

## 8. Чем не копия соседа

1. **Другая предметная область:** учётные записи и доступы к информационным системам, а не ремонт оборудования или логистика.
2. **Другой главный объект:** заявка на доступ (а не заявка на ремонт, не заказ, не обращение в поддержку).
3. **Другие роли:** сотрудник (инициатор) и администратор (исполнитель) — без третьей роли согласования.
4. **Другой справочник:** информационные системы, к которым запрашивается доступ (а не участки, оборудование или сотрудники).
